# v0.2 Agent 实现与实验交接

作者计划下一周完善 Agent 并开展实验。这里规定与论文一致的最小接口与记录，不是已经实现的功能声明。

## 1. 现状与目标

已有：人工选择诊断/调整动作，skill 完成配置、资源会话准备、压测 pipeline 与报告。

待实现：Agent 根据当前证据提出诊断技能，确定性检查器验证约束，执行器运行并记录，数值优化器提出配置，再独立验证。不要将历史人工决定的步骤写成 Agent 自主轨迹。

## 2. 技能调用的最小字段

每次调用保存：`task_id`、`run_id`、`controller_id`、`skill_id/version`、`action_id`、`context_hash`、模型与精度、部署及数据集标识、初始状态/时间协议、资源预算、输入证据引用、竞争解释、预期可区分观测、类型化参数、约束判定、动作结果、诊断结果、服务结果、恢复结果与全部成本。

诊断结果使用 `support / contradict / inconclusive`；前置条件缺失或不支持时独立记录 `not_executable`。服务结果分别包含进程存活、请求成功/总数及联合 SLO，不以其中一个替代另一个。历史备注是来源明确的经验，不是直接可用的根因真值。

## 3. 四类约束

| 检查 | 最小实现 | 经验如何参与 |
|---|---|---|
| 实际能力 | 操作与参数必须在本地版本能力清单中 | 旧经验不能创造后端不支持的选项 |
| 执行与状态 | 资源预留、类型/范围、干预边界、P/D 状态代次、恢复和预算 | R12–R14 提醒核对重启协议；不直接永久禁止 max_run96 |
| 评价 | 固定模型精度、负载协议、指标公式、SLO 与失败分母 | R19 提醒“无崩溃”不等于可行；缓存计入 TPM 要标明 |
| 复用 | 版本、拓扑、缓存、初始化、空闲状态变化触发检查/重放 | R32/R35 提醒连续长稳不能覆盖空闲恢复 |

必要检查对所有基线一致。未知状态先标未知并补观测；历史建议只改变搜索优先级，除独立确认的能力限制外，不永久裁掉合法配置。恢复失败须停止当前调用并记录，不能继续把污染状态下的测量当作匹配样本。

## 4. 下一轮先做的实验

1. 固定一个稳定镜像、模型和负载，补齐硬件/软件清单、计数公式与请求级时延；保存数据集与配置哈希。
2. 回收关键历史案例的原日志核验；当前 35 条仅作开发来源，冻结技能库后再设留出任务。
3. 对比受约束数值优化、同技能固定规则、同工具普通 Agent、完整方案；所有方法使用相同必要检查、相同初始知识与预算。
4. 以达到同一可行目标的耗时和卡时为主指标，分别报告最终资源与服务能力。部署、诊断、预热、恢复、失败及控制器推理均计成本。
5. 测试冷态、重复复用及空闲恢复；各核心点独立重复，搜索使用多个种子。已有 24 小时循环记录不视为大量独立重复。
6. 再补必要的 48/64 卡同资源配比点，以及主动诊断、重放、全局探索消融。未验收路由/并行支持前不预设布局可行。
