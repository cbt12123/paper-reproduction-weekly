**四、最终主线与可检验增量**

建议研究问题：**当 KV 传输和推理在真实设备拓扑上并发运行时，单独测得的 Prefill、Decode、传输能力是否会错误排序候选 PD 配置？能否通过少量并发校准，在固定总调优时间内更可靠地选择满足 SLO 的配置？**

工作假设 H1：部分配置下，打包/重排、传输、目标端导入与推理共享资源，使单独测速得出的配置排序与端到端排序不一致。是否存在这些阶段、是否实际争用，都必须由目标环境的 trace 和受控实验确认。RDMA 带宽低、CPU 忙或显存占用高的相关性本身不构成因果证据。

工作假设 H2：在已有网络拓扑与阶段容量模型上加入并发争用校准，可以改善候选排序或减少错误的可行性判断。不能只展示模型拟合误差下降；要展示它改变了配置决策，并改善独立负载上的端到端结果。

工作假设 H3：同等总调优时间下，该模型引导的搜索比强随机搜索、通用约束 BO/TPE、独立阶段调优更早获得高 goodput 的可行配置。若只比默认参数好、却与通用 BO 无差别，自动调参方法的贡献就不足。

拟形成三项相互连接的贡献：

1. 可复现的机制观察：具体传输路径在哪些配置与负载下造成排序失效，在哪些条件下影响很小。
2. 对应的配置选择方法：针对实际路径的并发校准与候选排序，而非重写整个推理框架。标准 BO/TPE 可以作为搜索器，但不是创新本体。
3. 完整的系统证据：SGLang 上实现，在 P800 目标环境用强基线、消融和留出负载验证效果；若有第二套硬件再验证可迁移性。

已知近邻与边界：HexGen-2 已考虑通信带宽，不能将其描述成“忽略通信”；FuseLink 已研究路径利用，不能声称“首次发现通信争用”；ECO 已使用结构模型和有限预算搜索，不能把类似组合重命名为算法。最终创新必须落在明确的、此前方法未解决或未充分验证的争用机制及其决策效果。

不建议在第一篇中加入：通用 Agent 规划/记忆/多智能体、全栈多模型管理、AFD、全新量化与 KV 压缩、无关算子集合。与该路径直接相关的 KV 打包/重排算子可以作为系统实现的一部分，其余留后续。

**五、方法设计初稿**

流程：环境能力检查 → 构建合法配置集 → 少量单阶段及成对并发测量 → 校准路径干扰 → 排序候选 → SLO 压测 → 更新模型 → 冻结配置 → 留出负载验证。

合法配置集先限制到实际已支持的功能。配置变量优先只取：P/D 资源比例、两侧 TP、prefill chunk/token budget、decode 活跃请求上限、实际存在的传输并发或缓冲参数。TP 等改变需要重启的选项按离线配置优化处理；主论文不声称它们能无损在线切换。后端不支持的参数明确标 N/A。

请求输入/输出长度、到达率和压力端并发上限是实验条件，不应在不同方法之间任意改变以制造收益。prefix cache、投机解码、量化、graph 等先固定，在独立实验中才讨论影响。

可用的解释性建模起点：

`TTFT ≈ 排队 + prefill + 未被重叠隐藏的传输关键路径 + decode 首步`。

传输路径按实际观察展开为打包/布局处理、设备侧搬运、网络传输、目标导入等；异步阶段不能机械全部相加。对于简单稳定流水线，可用 `min(P容量, 传输容量, D容量)` 作为瓶颈启发，但这既不是尾延迟公式，也不是已经建立的新理论；并发争用正可能使独立测得的这些容量失效。

先做低成本成对实验：相同 payload 下测纯传输；相同 decode 批次下测纯 decode；再并发运行二者；保持其余条件固定，改变传输并发/绑核或合法的路径配置。检查耗时变化、trace、吞吐和尾延迟，再确认哪个可控变量能够解释变化。若无法直接控制某个底层路径，不将其假设为可调策略。

**六、指标、基线与实验矩阵**

主指标采用 **SLO 约束下的请求 goodput**，同时报告输出 TPM。为每个请求定义 `ok = 完整成功 AND TTFT≤τf AND TPOT≤τo`，goodput 为单位测量时间内满足该条件的请求数量。拒绝、超时、OOM 或失败请求都不能算达标。所有方法采用同一输入请求集合、计时/预热/排空协议。除 goodput 外再报告相对于全部到达请求的达标比例，避免靠拒绝难请求提高结果。

TTFT 与 TPOT 的单独 P95 达标并不自动意味着 95% 请求同时满足二者；联合达标比例必须直接统计。TPOT 是每请求平均输出间隔，不能替代 ITL 分布或尾部卡顿；输出至少两个 token 的请求用于 TPOT，其他情况另行处理。

| 类别 | 建议报告 |
|---|---|
| 主结果 | joint SLO request goodput、联合达标率、SLO 下的可持续到达率 |
| 吞吐 | 输出 TPM；输入 TPM 单独列；不混合二者后作唯一指标 |
| 延迟 | TTFT/TPOT 的 P50/P95/P99，token 级 ITL 尾部；明确统计层级 |
| 机制 | KV 打包/重排、实际传输及导入耗时，并发退化、相关 trace、内存与链路状态 |
| 调优代价 | 总墙钟时间、占用的卡时、profiling/加载/重启/预热/失败时间、到达目标性能的时间 |
| 正确性 | 固定模型及精度；跨设备接续的输出/数值检查；改变精度时另做质量验证 |

| 必需基线 | 具体要求 |
|---|---|
| 同置 SGLang＋chunked prefill | 在相同总资源下认真调优；检验 PD 是否值得使用 |
| 原生 PD＋静态配置 | 用厂商/官方建议及有记录的人工调优配置；不能只保留弱默认值 |
| 独立阶段调优 | 分别优化 P、D、单独传输，再组合；用于验证排序失效 |
| 随机搜索 | 同配置空间、同总时间预算、多随机种子 |
| 通用约束 BO/TPE | 同空间、同预算，计入初始化及失败成本 |
| 通信容量/拓扑感知方法 | 可实现 HexGen-2 思路的兼容版本；若未跑原系统，明确称适配基线，不伪称完整复现 |

如果使用 vLLM 作额外框架基线，需先证实模型、量化、PD、KV 格式及硬件版本兼容；主方法在相同 SGLang 运行时中的对比优先，以免把框架差异误认为方法收益。当前硬件跑不了的 NVIDIA 原型，不能直接搬论文图表作为实验基线。

建议最小实验范围：两种实际稳定支持的模型或一个模型的两个规模；短输入短输出、长输入短输出、短输入长输出、混合长度四类负载；固定到达率与突发/变化负载分开测；轻载到饱和的若干到达率；至少两种可实现的资源配置或网络条件。主张跨平台时必须增加第二平台，否则结论范围限制为所测环境。

用开环到达控制研究 SLO/排队，闭环固定并发作为容量诊断补充。采集实际输出长度，不用 max_tokens 代替。合成负载控制长度与到达分布，公开 trace 用于外部有效性，内部 trace 在可公开的条件下补充。训练/选配置的请求与最终评估请求分开。

核心点至少三次独立测量，随机搜索和 BO 建议五个种子（以实际预算为准），报告区间及失败记录。P99 需要足够请求样本并说明不确定性；固定分钟数本身不保证尾分位可信。实验顺序做交错或随机化，防止时段负载与设备温度造成系统性偏差。

消融优先：去掉争用校准；只保留单独带宽模型；P/D 分别调优而非联合；不同校准预算。上述消融用于判断具体机制是否必要，不把 OOM 防护或 Agent 包装的开关当主消融。

**七、回公司后最先做的实验与收敛规则**

已根据用户“资源池丰富、不必固定卡数”的补充更新为《资源池P800容量规划与实验设计_2026-10-18.md》。固定 32 卡下的 8P+24D、16P+16D、24P+8D 保留作受控子实验；主实验允许总资源变化，比较同负载与同 SLO 下的分配卡数，以及整条资源—达标吞吐曲线。加卡带来的吞吐增长与方法提升分别报告。

先只用一个稳定模型、固定精度和总卡数，完成以下顺序：

1. 同置与原生 PD 均跑通，正确性与计时协议一致。
2. 对 3—5 个合法的 P/D 配置做独立阶段测量与端到端测量，检查排序是否不同。
3. 对最可疑的传输路径做纯传输/纯 decode/二者并发的对照，重复验证。
4. 用同样资源和压力条件比较强人工配置、小预算随机搜索与拟议校准选择器。

这里的 3—5 个配置是预研范围建议，不是足以支持最终论文的统计样本承诺。

若发现可重复的排序错误、能追踪到机制、并且校准会改善选择，继续主线。若争用效应很小或模型修正没有改善决策，则不应先写定“争用显著”的结论；应根据新证据收敛到 PD 盈亏边界/配置稳健性等问题，并再次检索对应研究。若只获得“在 P800 上跑通、调几个参数提高 TPM”，目前证据仍不足以支持目标论文，不建议通过包装 Agent 掩盖缺口。
