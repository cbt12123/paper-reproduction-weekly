检索与修订日期：2026-10-18。

**本轮结论**

此前方案主要是研究问题、容量规划目标和实验安排，尚不足以构成清晰的方法创新。用户希望 Agent 与 skill 进入论文主体，本轮将方法主线调整为：**针对 PD 耦合瓶颈的主动诊断，利用带适用条件与反证记录的诊断技能，驱动配置结构选择和数值优化。**

工作题目：**《基于诊断技能复用的 SGLang PD 分离推理 Agent 自动调优》**。

英文工作题目：**Diagnostic Skill Reuse for Agentic Autotuning of Disaggregated LLM Serving in SGLang**。

这是一项候选方法设计，尚没有实验结果，不能声称已经证明新颖性或能保证二区/三区录用。Agent 自动调参、经验记忆、规则积累、性能诊断均已有先行工作。最终增量必须由 PD 场景中的具体技术设计、与近邻的比较以及留出任务结果共同建立。

硬件与投稿约束继续保留：AMD EPYC 主机＋P800，已知起点 4×8 卡，支持 RDMA，资源总量可变；腾讯署名；2026 年 11—12 月首次投稿；中科院大类二区/三区；接受混合期刊的非 OA 路径。

**一、创新具体落在哪里**

候选贡献 A：PD 结构感知的主动诊断与分层搜索。

同一种用户可见症状（例如 TTFT 上升）可能对应 P 队列、KV 传输等待、D 接纳等待等不同原因。Agent 维护多个待验证假设，根据当前证据选择能区分它们的诊断 skill，再决定探索 P/D 数量、拓扑/传输参数还是阶段内参数。标准约束优化器负责具体数值搜索。

要实现的技术包括：阶段依赖表示；症状到可执行诊断的映射；诊断成本与区分能力的选择策略；从诊断结果产生参数子空间或软先验；证据不充分时重新探索。通用主动学习、BO 或工具调用本身不作为新发明；贡献在 PD 耦合条件下这一诊断—搜索机制是否必要且有效。

候选贡献 B：具有适用边界和反证记录的诊断技能复用。

技能复用对象包含诊断过程、成立条件、干预后的预期观测和历史证据，不能只是复制上一轮最优参数。跨模型、输入输出分布、集群规模或软件版本复用前，先检查兼容性并按需要做低成本验证；被反驳的知识降权或停用。使用软先验与保留探索，避免错误技能永久剪掉好配置。

关键研究问题是：相较全文日志检索、单纯经验规则或无条件复用，适用性检查能否在新任务上减少错误迁移并降低达到目标性能的耗时。数据结构采用 JSON/YAML、建立一个技能目录、加入 LLM 记忆，不单独算贡献。

系统实现与实验是以上两项机制的证据。P800、资源丰富、测试点多、自动生成报告和 Agent 数量多，都不能替代方法增量。

**二、Agent、skill 与优化器各做什么**

| 组件 | 承担的决策 | 可衡量的作用 |
|---|---|---|
| LLM Agent | 整合文档、结构化指标与 trace 摘要；提出待验证假设；选择诊断 skill；决定下一轮优化哪组变量 | 更少无效诊断/重部署，更快定位并形成高质量候选 |
| 诊断 skill | 执行有边界的诊断程序并返回标准证据，明确成功、失败和不确定 | 相同任务可重复执行，跨任务可检查适用性 |
| 数值优化器 | 在合法子空间或软先验下选择具体参数值、资源数量 | 避免让 LLM 凭自然语言猜全部数值 |
| 执行与验证层 | 检查参数能力、部署、压测、解析、记录、恢复配置，独立计算性能与可行性 | 保证比较协议一致，并避免 Agent 自行判定收益 |
| 技能证据库 | 保存来源、上下文、干预结果、支持与反证，检索后验证适用性 | 在留出任务上验证复用价值和误用代价 |

流程：收集状态 → 检索候选技能 → 检查适用条件 → Agent 选择诊断 → 执行并获得证据 → 更新假设 → 选择参数族 → 优化器搜索 → 独立验证 → 更新证据库。

如果去掉 LLM 后固定规则能取得相同效果，应如实缩小 Agent 的贡献，不能只凭流程图声称必须用 Agent。与规则控制器比较时，给它相同工具、相同观测与同一初始知识库。

**三、把现有 skill 升级成什么**

现有自动部署和压测 skill 可直接作为基础执行能力。再增加少量 PD 诊断技能，首版先覆盖：prefill 压力、decode 接纳/容量压力、P/D 配比、KV 传输与计算并发影响。具体诊断结论由平台能观测的指标和可控变量决定。

一个诊断 skill 最少包含：

| 字段 | 内容 |
|---|---|
| 适用条件 | 模型/注意力与 KV 形式、后端、版本、拓扑、参数能力、负载特征 |
| 输入证据 | 请求级 TTFT/TPOT、阶段队列或等待、实际传输记录、已有 profiler 数据 |
| 待验证假设 | 该技能旨在支持或排除的瓶颈解释 |
| 诊断动作 | 有控制变量的测量或配置干预；记录代价与需重启项目 |
| 预期观测 | 在假设成立/不成立时，分别期待哪些指标如何变化；允许无法区分 |
| 可调参数族 | 若得到支持，哪些结构或数值参数值得优先探索 |
| 恢复与约束 | 对应的恢复配置、兼容性和计时要求 |
| 历史证据 | 运行标识、前后配置、负载、重复测量、区间、支持和反证记录 |

示例仅为假设，不是平台已测结论：TTFT 高时，Agent 同时保留“P 侧不足”和“KV 等待增加”两个解释。优先读取已有阶段记录；仍无法区分时，再调用能分离搬运与推理影响的成对诊断。结果支持计算瓶颈才重点探索 P 资源；结果支持传输问题才重点探索已有合法的放置/传输配置。不能用单一 NIC 使用率或一次前后改善证明因果，也不能预设必须主机中转。

首版技能由工程师编写和验收。Agent 可以提出新的技能草案或更新证据，但自动生成和自动发布技能不是首次投稿必需功能。把这些未来扩展单列，避免同时承担技能生成、代码修复和在线伸缩三个研究问题。

**四、与近邻的实质边界**

- GPTuner 已用 LLM 从文档提取知识，选择参数并缩小搜索空间。新方案不能只把数据库名改成 SGLang。
- STELLAR 已让 Agent 分析日志、调参并积累规则。因此“分析 Agent＋调优 Agent＋记忆”并非新颖结构。
- SysInsight 已将源码知识、实测规则和在线诊断结合。诊断、可验证规则和置信更新等概念也不能泛称首次。
- SCOOT 已针对推理引擎做约束 BO 与并行搜索；默认参数提升不是充分对照。
- AutoTuneBench 已研究 Agent 调优测量可信性。规范记录和独立评估是必要协议，不是当然的新贡献。

本方案要争取的具体增量是：**PD 多阶段耦合下，对诊断动作及技能适用性进行显式选择和验证，以改善跨负载/规模的资源与配置决策。**仍需进一步逐段对照 STELLAR、SysInsight 等原文，确认新增机制及验证任务没有重复；“第一次在 P800 上做”不是充分理由。

**五、如何证明 Agent 与 skill 有价值**

主比较采用相同合法配置空间和一致的 SLO/负载。总资源数可变，目标包括同一服务要求下的分配卡数、同等调优成本下的好配置，以及最终 goodput。

| 方法 | 相对完整系统的关键差别 |
|---|---|
| 强人工/厂商配置 | 作为端到端工程基线；明确已有投入 |
| 通用约束 BO/TPE | 有数值搜索，无 LLM 诊断与技能复用 |
| 固定规则＋相同工具和技能 | 检验 LLM 决策是否必要 |
| 普通工具调用 Agent | 有部署/压测工具，无专门诊断选择机制和适用性验证 |
| Agent＋原始日志检索 | 检验结构化诊断技能相对简单检索的作用 |
| Agent＋技能，无适用性检查 | 检验负迁移与版本/上下文误用 |
| 完整方案 | 主动诊断、技能适用性检查、分层搜索和独立验证 |

为控制工作量，先完成 BO、规则控制器、普通 Agent、完整系统四项主比较，再做技能记忆和适用性检查消融。各对照共享同样源文档、可用观测和基础工具；不能通过给完整系统额外手工经验制造收益。

新增评价指标：达到预先固定的 SLO/goodput 目标所需墙钟时间和分配卡时、无效配置和失败率、诊断调用次数、结构重配置次数、留出任务上的技能迁移收益及错误复用率。诊断正确性只有在受控机制已知或经独立证据验证时才评价；其余采用置信度和不确定结果，不能把 Agent 的解释当标准答案。

所有方法计入 profiling、诊断、部署、重启、预热、失败恢复与 Agent 推理开销。丰富资源允许并行实验，但对照方法享有一致并发资源上限，或使用统一卡时预算，不能只按试验次数比较。

先在源任务积累技能证据，冻结初始技能库，再对留出的模型/负载/规模评估。测试任务不得提前写进技能库。明确冷启动和热启动，区分离线建库成本与在线收益；在线更新与静态库分别报告。

如果仅有“比无调优好”或“比弱 Agent 好”，还不能说明方法优于已有强调参。若只提升人机交互或报告可读性，论文主张应限定为工具研究，不能继续声称推理性能方法突破。

**七、针对投稿的决定**

JSA 有直接的推理服务策略文章，FGCS 有资源编排和诊断调优先例。可以将它们作为两种写法的主要内容对标：突出 PD 阶段耦合与配置机制时对标 JSA；突出 Agent 决策、技能迁移及资源管理时对标 FGCS。JPDC 保留候选，不因拥有更多机器就自动升级投稿目标。

历史分区与非 OA 路径仍引用主调研记录：2025 中科院大类 JSA 3 区、FGCS 2 区为公开转载数据，尚未获得官方逐刊核验；三者的最终发表路径以投稿时作者指南和腾讯采用口径为准。本轮不把相关论文所在刊都列为符合要求的投稿目标。

建议首版聚焦一个 Agent 控制器、4 类诊断 skill 和一个成熟数值搜索器；做源任务到留出负载/规模的技能迁移。无需把多 Agent、源码自动改写、全套算子生成和在线伸缩同时作为贡献，避免超过 11—12 月首次投稿窗口。

**八、现在可完成的具体产物**

可先做 Agent 的状态/动作定义、技能 schema、首批技能契约、诊断选择策略、参数族映射、失效与重新探索策略、对照协议和论文方法草稿。现有脚本接入后，再通过真实数据决定是否值得继续；不能预写加速数字。

该论文最终应能写出一句有证据的贡献描述：在指定模型、负载和 P800 集群范围内，诊断技能的选择与适用性验证，如何改变了配置决策，并相对同工具规则、普通 Agent 和强数值搜索改善了何种指标。若实验不支持，不能用新的系统名称替代证据。
