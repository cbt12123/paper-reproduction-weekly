# 同类论文阅读清单（2026-10-13）

> 按与你的论文（P800 + SGLang + DS V4 Pro，mP:nD 调参，TPM 优化 + 调参 Agent）的相关度分组。
> 标 ⭐ 的为必读。

## A. 直接同类：PD 分离的配置扫描/实证研究（必读 + 投稿前必须划界）

### ⭐ A1. Beyond the Buzz: A Pragmatic Take on Inference Disaggregation（NVIDIA，MLSys 2026）
- 链接：https://proceedings.mlsys.org/paper_files/paper/2026/hash/d49cee5f3a79d97d719df255689d83d7-Abstract-Conference.html
- **做了什么**：首个大规模系统性研究解耦推理的工作。扫描**数十万个设计点**，覆盖多种负载与硬件配置，分析吞吐-交互性（TTFT）Pareto 前沿。
- **核心发现**：解耦对 prefill 占比高的流量和大模型收益最大；**动态速率匹配 + 弹性伸缩**是实现 Pareto 最优的关键；配合 NVIDIA Dynamo 落地。
- **为什么必读**：这就是你要写的体裁在顶会的样子。它的"设计点扫描 + Pareto 前沿 + 发现列表"结构可以直接对标你的 mP:nD 扫描。
- **你的划界句**："Beyond the Buzz 在 NVIDIA 硬件 + Dynamo 生态下扫描设计空间；本文在国产 XPU（P800）上实证，并给出低成本搜索方法（Agent）而非大规模离线扫描。"

### ⭐ A2. Optimizing Deployment Configurations for LLM Inference（Meta，MLSys 2026）
- 链接：https://proceedings.mlsys.org/paper_files/paper/2026/hash/97dc07f1253ab33ee514f395a82fa7cc-Abstract-Conference.html
- **做了什么**：Meta（Llama 服务 10 亿月活）系统化分析**数百万种部署配置**：硬件（H100/H200/MI300X）× 并行策略（TP/PP/EP/CP/DP）× 运行时（continuous batching vs PD 分离），目标"满足延迟 SLO 下最大化吞吐"。
- **经验教训**：连续批处理 vs PD 分离的取舍、不同推理阶段适合不同并行策略、异构硬件组合、MoE 架构的系统级影响。
- **为什么必读**：这是你的 L3（配置选择）在工业极限规模的版本。重点学它怎么组织"配置空间"的叙述，以及它承认哪些问题没解决。
- **你的划界句**："Meta 依赖大规模离线扫描，成本高昂；本文面向预算受限场景，用主动搜索 Agent 把调参成本降到 X 次实验，并在国产硬件上验证。"

### ⭐ A3. Revisiting Disaggregated LLM Serving for Performance and Energy Implications（IBM/UIUC，EuroMLSys'26，arXiv 2601.08833）
- 链接：https://arxiv.org/abs/2601.08833
- **做了什么**：在不同 KV 传输介质（显存直传/主存中转/存储中转）下重新评估 PD 分离，加了共置基线，用 DVFS 分析给出性能-能耗 Pareto 前沿。
- **核心发现**：① PD 分离的性能收益**取决于负载与 KV 传输介质**，非必然；② 分离架构**不省能**，即使阶段独立调频也无法弥补其固有能耗开销。
- **为什么必读**：方法论与你的 L1/L2 高度相似（重新评估 + Pareto + 机制归因）。它的"分离不一定好"结论给了你一个 hook——"该结论在国产 XPU 的算力/带宽配比下是否成立？"这本身就可以是你的研究问题之一。

## B. 系统类：相关工作引用 + 学动机实验写法

### B4. DistServe（OSDI'24）
- **为什么读**：学**动机实验写法**——先用干扰实验坐实"prefill 拖垮 decode 的 TTFT 尾延迟"，再提分离系统；goodput@SLO 指标的出处。你的 Introduction 应该长这样。

### B5. Mooncake（FAST'25，arXiv 2407.00079）
- **为什么读**：KV cache 中心的分离架构，HiCache/L3 缓存相关工作的引用源头。你扫 HiCache 开关时的相关工作。

### B6. Sarathi-Serve（OSDI'24）
- **为什么读**：chunked prefill + TBT SLO；同时它是"共置/混合部署"路线的代表——你论文里 PD 分离的对照基线理论依据。

### B7. Splitwise（ISCA'24）——选读
- **为什么读**：按阶段拆分到不同机器的先行工作，相关工作引用用。

### ⭐ B8. TaiChi: Prefill-Decode Aggregation or Disaggregation?（arXiv 2508.01989）
- **为什么读**：正面回答"聚合 vs 分离哪个好"并做统一系统。你必须在 Related Work 引用并划界（他们造系统于 GPU，你实证于国产 XPU）。

## C. 配置选择方法：你 L3 的对标

### ⭐ C9. Vidur（Microsoft，arXiv 2405.05465）
- 链接：https://arxiv.org/abs/2405.05465 · 代码：https://github.com/microsoft/vidur
- **做了什么**：LLM 推理的高保真离散事件仿真器（延迟误差 <9%），Vidur-Search 用仿真代替真实压测搜索最优配置。
- **为什么必读**：你的"配比选择器/Agent"最直接的先前工作。划界：Vidur 靠仿真（需要 GPU profiling 建模、对新硬件如 XPU 需重新校准），你靠真机上的主动搜索/轻量实测模型——在仿真难以覆盖的国产新硬件上，你的路线更可行。
- **写作技巧可抄**：它把"搜索成本 vs 全网格"的对比做成了核心卖点（省 X 万美元 GPU 时）——你的 Agent 也这么做。

### C10. LLM-Pilot（IBM，SC'24，arXiv 2410.02425）——选读
- **为什么读**：在新硬件上做 profiling + 性能预测 + 选 serving 配置以最大化 SLO 达成率。与 Vidur 一起构成"预测派"，与你的"实测搜索派"对比。

## D. 体裁范本：学写作

### D11. Benchmarking LLM Inference on Apple Silicon（SIGMETRICS PER 2026，Benazir & Lin）
- **为什么读**：单硬件平台 characterization study 的文体模板——Finding 怎么编号、局限怎么写、"别人为什么关心单平台结论"怎么论证。你的论文整体长这样。

### D12. Energy-Aware Multilingual Evaluation（Electronics 2026, 15(7):1395）
- **为什么读**：统计检验（Friedman/Wilcoxon）+ Pareto 前沿分析的方法论模板。你做 (TPM, TPOT P99) Pareto 时直接搬。

### D13. EcoInfer（Electronics 2026, 15(10):2139）
- **为什么读**："3 个实测观察 → 3 个挑战 → 3 个模块"的观察驱动写法，以及中等期刊的接收标准。

## 建议阅读顺序（时间紧就按这个来）

1. **Beyond the Buzz**（半天）——定体裁骨架：设计点扫描 + Pareto + 发现列表
2. **DistServe**（半天，只精读 §1–3 动机实验和 goodput 定义）——学 Introduction 和指标
3. **Revisiting**（半天）——学"重新评估"论文怎么立问题，同时抄 DVFS/Pareto 方法
4. **Vidur**（1 小时，精读 Vidur-Search 一节）——学"搜索成本"怎么卖成贡献
5. **Apple Silicon**（1 小时，看 Finding 组织和 Limitations）——学单平台结论怎么辩护
6. 其余（TaiChi、Mooncake、Sarathi-Serve、Meta 那篇）按 Related Work 需要查阅

## 对你最重要的战略信息

- **好消息**：你的体裁（PD 分离配置扫描 + 发现 + 选择方法）2026 年刚在 MLSys 上被 NVIDIA 和 Meta 各发一篇——说明这个体裁天花板很高，审稿人认可"实证+配置指导"的价值。
- **坏消息/机会**：这两篇都在 NVIDIA/Meta 硬件生态，**国产 XPU 上没有任何对应工作**。你的平台差异是天然的护城河；但同时你必须读它们，因为审稿人（很可能熟悉这两篇）会直接问"你和 Beyond the Buzz 的区别是什么"——答案就是：平台（P800 vs H100/MI300X）、模型（DS V4 Pro 的 MLA+MoE）、搜索方法（低成本 Agent vs 大规模扫描）三条。
- **A3 的"分离不一定好"结论**给了你一个免费的研究问题：在 P800 上验证/反驳它。
