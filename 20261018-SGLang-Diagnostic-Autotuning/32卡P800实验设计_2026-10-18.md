**选题决定**

继续采用《面向 PD 分离大模型服务的传输争用感知联合配置优化：基于 SGLang 的设计与评估》。研究对象是同类 P800 加速器组成的集群；AMD CPU 是主机环境。硬件异构不作为贡献主张。

固定资源下，联合选择 P/D 实例配比、合法节点放置和少量关键运行参数，在 TTFT/TPOT 约束下提高请求 goodput，或降低达到目标配置的总搜索成本。重点验证单独阶段容量与真实并发能力的差异是否会改变决策。研究假设仍待实测，当前没有声称平台存在 NUMA/PCIe/RDMA 争用。

**资源预算与布局**

以下每实例 TP8 的布局以“模型及运行时已支持单节点 8 卡完整实例”为条件。必须在同一实验组内固定模型、精度、上下文和软件版本；P 与 D 各存一份所需模型权重，不能将其当成简单的权重切层分配。

| 总卡数 | 同置基线 | PD 候选 | 用途与前提 |
|---|---|---|---|
| 8 | 1 个 TP8 同置实例 | 4P+4D，仅限模型确实能以 TP4 分别运行 | 最小规模；若 PD 不可行，该点仅报告同置，不为凑曲线更换模型 |
| 16 | 2 个 TP8 同置实例 | 8P+8D，即 1P1D | 最先跑通的主预研配置 |
| 32 | 4 个 TP8 同置实例 | 8P+24D / 16P+16D / 24P+8D，即 1P3D / 2P2D / 3P1D | 固定预算的主实验，区分阶段配比与算法收益 |

如果目标模型需要单实例跨节点，以上表格按实际可行实例粒度重排。额外的 64 卡扩展仅在主实验完成、结论需要规模验证时使用，不作为首次投稿的前置条件。

负载发生器向统一入口施压。同置多副本与 PD 多实例均记录并合理配置路由策略。原生运行时/网关支持多少 P/D 实例配对、连接以及负载均衡，要先做功能检查，不能因为资源数量足够就默认任意布局已支持。

**第一轮：只做足以决定选题的实验**

选择一款现有环境已经稳定支持的模型和一种固定精度，先用 16 卡做同置与 1P1D 功能及测量验证。然后用 32 卡比较三个节点级 P/D 配比。无需先扩大硬件或开发完整 Agent。

1. 建立环境清单：模型/tokenizer 标识和版本、权重精度、KV 精度、SGLang commit/镜像摘要、Kunlun 插件与驱动、卡内存、NIC 数量与速率、实际 NUMA/PCIe/NIC/XPU 拓扑。
2. 确认客户端到达时间、服务端排队、首 token、后续 token、完成和错误记录。核对是否存在客户端排队或压测端瓶颈。
3. 记录 KV 实际走的路径：源端处理、搬运、网络、目标端处理，哪些异步重叠。逐个检查时间戳语义；未暴露的阶段标为不可观测，不能把推算当实测。
4. 先跑长输入短输出和短输入长输出两种负载，在相同到达序列和 SLO 下比较三个 P/D 配比。
5. 比较独立阶段测量推荐的配置与端到端实测排序。找到可重复的差异后，再对可疑路径做纯传输、纯 decode、并发二者的受控测量。

优先控制已有合法参数：传输并发/缓冲、CPU 亲和性或实例放置。若后端没有暴露某项控制，先选择已有控制或只做机制分析，避免提前承诺底层重写。亲和性实验先从实际拓扑出发，当前不预设最优绑定方案。

节点间“支持 RDMA”不能直接当作可用传输带宽。需要区分单连接有效带宽、多个连接汇聚带宽、与推理并发时的退化。测量单向/双向与实际业务传输方向；网络类型及带宽以设备和测量记录为准。

若能抓取设备 trace，可定位内存访问、搬运和 kernel 的重叠；CPU 使用率或 NIC 利用率单独变化不能证明瓶颈。先做保持 payload 与 decode 批次一致的成对实验，再用端到端服务验证。

**第二轮：验证方法，而不是只验证参数调得更好**

首版配置空间只保留 4—6 类变量：P/D 实例配比、合法 TP（默认先固定 TP8）、prefill token/chunk budget、decode 活跃请求上限、已支持的传输并发或缓冲参数，以及必要的拓扑放置。实际取值从环境测量和可行性检查产生，不填未经验证的厂商参数。

配置选择器先用单阶段测量构建容量模型，然后投入少量并发校准测量，修正可行性和候选排序，再执行端到端压测。搜索器可采用标准随机搜索或约束 BO/TPE；研究贡献应归于新增机制是否改善选择，而非将标准优化器重命名。

| 对比方法 | 需要控制的条件 |
|---|---|
| 调优后的同置 SGLang | 同总卡数；保留可用的 chunked prefill 与公平路由 |
| 调优后的原生静态 PD | 使用可追溯的人工或官方建议配置，明确调优投入 |
| 独立阶段容量模型 | 同样的部署候选，缺少并发干扰校准 |
| 随机搜索 | 相同合法空间、相同总调优时间、多随机种子 |
| 通用约束 BO/TPE | 相同空间与预算，计入初始化及失败成本 |
| 拟议方法 | 计入单阶段 profiling、并发校准、部署、重启、预热和失败的全部成本 |

对于通信拓扑感知的已有方法，优先复用其算法或构造明确标注的适配基线。不能将已考虑网络带宽的 HexGen-2 描述为“没有考虑通信”。若只比较独立阶段模型，不能据此宣称超过所有已有异构调度系统。

记录最优可行 goodput 随总调优时间变化的曲线，并报告最终被冻结配置在独立请求集合上的效果。只在试验次数相同时比较会忽略不同配置启动成本；主比较用相同卡数、相同总时间，附加报告卡时和试验次数。

同一预先选定目标性能可用于比较达到目标的时间；在约定预算内没有达到的运行如实记为未达到，不从汇总中排除。

**负载与指标**

正式实验可扩展到两款稳定模型或两个规模。优先选择已有适配的模型，明确精度与质量一致性；不要仅为追新增加模型适配工作。

| 工作负载 | 目的 |
|---|---|
| 短输入、短输出 | 看框架/排队开销及低负载下 PD 的代价 |
| 长输入、短输出 | 增强 prefill 与 KV 搬运压力 |
| 短输入、长输出 | 增强 decode 压力 |
| 长短混合、长度有方差 | 验证平均长度不能代表实际服务负载 |
| 独立的突发或阶段变化 trace | 检查冻结配置的稳健性；若未实现在线部署切换，不称为在线自适应系统 |

具体长度必须在模型和环境验证后固定，主实验不预先假定某个最大上下文。比较时固定请求集合、输出长度控制、缓存状态、到达过程和 SLO。合成负载用于归因，公开 trace 或允许公开的内部 trace 用于外部有效性。

主指标：同时满足 TTFT 和 TPOT 阈值且完整成功的请求数/时间；同时报告以全部到达请求为分母的联合达标率。失败与拒绝计入未达标。输出 TPM 单列，输入 TPM 不与其混合。

补充指标：TTFT/TPOT 的分位数、token 级 ITL 尾部、队列长度或排队时间、KV 路径耗时、吞吐、调优墙钟时间与卡时。P95 TTFT 和 P95 TPOT 分别达标不等价于 95% 请求联合达标。用开环到达控制研究排队和 SLO，闭环固定并发用于容量诊断。

SLO 阈值在正式比较前固定，可选宽松/严格两档并做敏感性分析。所有方法采用同一档阈值；对多节点设置不能各自重定义更宽松的阈值以维持达标。

2. 隔离/并发时的传输与 decode 行为：解释机制。

**完成标准与投稿策略**

JPDC 仍为默认目标，FGCS 为条件冲刺：需要有可重复的机制观察、明确方法增量、强基线和消融，以及多负载与规模证据。32 卡提供了实验条件，但不会自动提高分区或保证录用。期刊分区与发表路径的证据边界沿用主调研文件。

如果新增校准没有改变最终选择或搜索效率，应收窄或重设研究问题；不能仅靠扩大到 64 卡掩盖方法无增益。若只有某一个配置下提升，论文需要明确适用条件及退化案例。

用户确认测试可动态安排，因此原先假定“11 月才可开始”的等待条件不再是前置约束。以第一周完成机制预研为起点，后续约两周完成最小方法和主要对照，再约两周补足验证并并行写作；公司发表流程同步推进。目标继续为 2026 年 11—12 月首次提交，日历安排以实际首轮结果及可用卡时校准。
